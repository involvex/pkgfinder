# AGENTS.md – Agent Guidelines for pkgfinder

Guidelines for AI agents and contributors working in this repository.

## Project Overview

`@involvex/pkgfinder` is an interactive npm registry search TUI. It improves the classic
`npm find` / `npm view` workflow: live `/` search, a rich package detail view, pagination,
sorting, and one-key browser shortcuts (`o` = npm page, `b` = repository/homepage).

- **Runtime**: Node >= 18 (also the bundler and test runner)
- **UI**: [Ink](https://github.com/vadimdemedes/ink) 7 (React 19 for CLIs)
- **Registry API**: public `registry.npmjs.org` – free, no API key
- **Dependencies**: `ink`, `react`, `ink-text-input`, `meow`, `react-devtools-core`
- **Module system**: ESM (bundled to `dist/cli.js` by Bun)
- **Binary**: `pkgfinder` (`bin` → `dist/cli.js`)
- **Language**: TypeScript, strict mode

## Useful Commands

### Development

```bash
# Install dependencies (Bun only – never npm/yarn/pnpm)
bun install

# Run in development mode (hot reload)
bun run dev
# or directly with arguments
bun run src/cli.tsx "react hooks"

# Build for production
bun run build        # outputs dist/cli.js

# Run the compiled binary
node dist/cli.js --help

# Global install for testing the binary
bun link
pkgfinder "react hooks"
```

### Code Quality

```bash
# Lint with ESLint (flat config)
bun run lint

# Auto-fix lint issues
bun run lint:fix

# Format with Prettier (uses shared @involvex/prettier-config)
bun run format

# Type-check with TypeScript (tsc --noEmit)
bun run typecheck
```

### Testing

```bash
# Run all tests (mocked fetch – no network access)
bun test

# Run a single test file
bun test test/registry.test.ts

# Run tests matching a pattern
bun test --grep "retry"
```

### Publish

```bash
npm publish          # scoped @involvex package
```

## Architecture

```
CLI (src/cli.tsx) ──> App (src/app.tsx) ──> registry (src/registry.ts) ──> npm registry
        │                     │                        │
        │                     └──> components/*         └──> RegistryError (exitCode)
        └──> open.ts (browser)  └──> open.ts
```

- **CLI entry** (`src/cli.tsx`) parses flags with `meow`. In `--json` mode it prints
  `{total, results}` and exits; otherwise it renders `<App>`.
- **App** (`src/app.tsx`) is a small state machine with two screens (`search`, `detail`),
  a debounced live search, and a `requestId` race guard so stale responses are dropped.
- **registry** (`src/registry.ts`) is the only module that talks to the network:
  - Search: `GET https://registry.npmjs.org/-/v1/search?text=&size=&from=&quality=1|popularity=1|maintenance=1`
  - Details: `GET https://registry.npmjs.org/<name>` (scoped names are `encodeURIComponent`-encoded)
  - 10 s timeout via `AbortSignal.timeout`
  - One retry on HTTP `429`/`5xx` with 500 ms backoff (`Bun.sleep`)
  - HTML body (not JSON) is detected and reported as likely rate-limiting
- **Error model**: `RegistryError` carries an `exitCode` (default `2`).
  Exit codes: `0` success · `1` usage error · `2` API/network error.

## Best Practices and Guidelines

### Language Conventions

- **User-facing strings are English** (help text, error messages, status bar, spinner
  labels). Keep them English and consistent with the existing wording in `src/`.
- **Code identifiers are English** (variables, functions, types, files).
- File names: kebab-case (`open.ts`, `registry.ts`). Functions: camelCase.
  Types/classes: PascalCase (`SearchResult`, `RegistryError`).

### TypeScript

- Strict mode is enabled (`"strict": true`).
- `"moduleResolution": "bundler"` → **relative imports use the `.js` extension** and
  resolve to `.ts`/`.tsx`: `import App from './app.js'` (do not write `.ts`).
- `"jsx": "react-jsx"` – no `import React` needed.
- `noEmit: true` – TypeScript only type-checks; Bun does the bundling.
- Keep `typescript` pinned to `^6`. **Do not upgrade to TypeScript 7** – `typescript-eslint` rejects it.
- `.tsx` files for JSX; `.ts` for non-JSX logic.

### Code Style

- Formatted by Prettier via the shared config `@involvex/prettier-config` (referenced with
  the `prettier` key in package.json – do not create a local `prettier.config.js`).
- Semicolons: yes. Quotes: single. Indentation: tabs. Trailing commas: none.

### Linting

- `eslint.config.mjs` (flat config): `typescript-eslint` recommended + `eslint-config-prettier`,
  globals for Node.js and Bun, ignores `dist/**`, `node_modules/**`, `bun.lock`.

### Testing

- Tests use `bun:test` (`describe`/`test`/`expect`/`mock`).
- **Never make real network calls in tests** – mock `globalThis.fetch` (see `test/registry.test.ts`).
- TUI tests use `ink-testing-library` v4 `render()` + `stdin.write()` and assert on
  `lastFrame()`. The renderer is async – always `await delay(...)` before asserting.
- `afterEach(() => mock.restore())` to clean up fetch mocks.
- Add tests for every new behavior (parsing edge cases, error paths, exit codes).

### CLI Design

- Argument parsing uses `meow` with `--json`, `--sort`, `--limit`, `--version`, `--help`.
- **Do not call `process.exit()` after an `await` on Windows** – it triggers a libuv
  `UV_HANDLE_CLOSING` assertion with pending fetch handles. Use `process.exitCode` and let
  the process exit naturally (or structure code so the TUI render is only reached in
  interactive mode).
- `--json` mode must never render the TUI (stdin is not a TTY in pipes).

### Dependencies

- Keep runtime dependencies minimal. `react-devtools-core` is required by Ink at bundle
  time – **do not remove it** (the build fails without it).
- New dev dependencies only when necessary; use `bun add -d`.

### Generated Files

- `dist/` is generated by `bun run build` and gitignored – never edit or commit it.
- `bun.lock` is committed (use `bun.lock`, not `bun.lockb`).
- AI agent directories (`.agent`, `.agents`, `.claude`, `.gemini`, `.kilo`, `.kilocode`,
  `.opencode`) are prettier- and git-ignored.

### Development Workflow

1. Create a feature branch from `main`.
2. Make changes in `src/` (and `test/` for new behavior).
3. Run `bun run lint` – must pass.
4. Run `bun run typecheck` – must pass.
5. Run `bun test` – all tests must pass (no network access in tests).
6. Run `bun run format` to normalize formatting.
7. Commit with a descriptive message (conventional style, e.g. `feat:`, `fix:`, `chore:`).

## Common Pitfalls

1. **Do not use npm/yarn/pnpm for dependency management** – Bun only (`bun install`, `bun add`).
2. **Do not edit or commit `dist/`** – it is generated by `bun run build`.
3. **Do not remove `react-devtools-core`** – Ink imports it at bundle time.
4. **Do not hit the real npm registry in tests** – always mock `globalThis.fetch`.
5. **Do not upgrade to TypeScript 7** – keep `^6` (typescript-eslint incompatibility).
6. **Do not use `ink-testing-library` v3** with Ink 7 – `useInput` renders empty frames;
   use v4.
7. **Do not drop the `.js` extension from relative imports** – `moduleResolution: "bundler"` requires it.
8. **Do not call `process.exit()` after `await`** on Windows – use `process.exitCode`.
9. **Do not translate user-facing strings to German** – CLI output (help, errors, status
   bar) is English by design.
10. **Do not introduce a different CLI framework** – `meow` is sufficient.
